# 🛡️ approved Quarantine Execution Gate

This document outlines the safety policies, operational commands, and validation mechanisms for executing duplicate file quarantines under Phase 12B of the Brilliantaire OS maintenance framework.

## 📋 Safety Rules & Guardrails

### 1. Purpose
The Approved Quarantine Execution Gate exists to securely move duplicate files staged by Phase 12A into a controlled quarantine location (`outputs/cleanup/quarantine/`). It operates under strict containment rules to ensure no data is lost or permanently deleted.

### 2. Approval Rule
No file move operation is executed without:
1. A valid staged quarantine plan (`outputs/cleanup/staging/duplicate_quarantine_plan_YYYY-MM-DD.md`) generated by the staging gate.
2. Explicit CLI confirmation using the `--confirm` flag passed to the `execute-approved` subcommand.

### 3. Quarantine-Only Rule
This gate is **Quarantine-Only**. Files must be moved, not deleted. Direct `rm` command usage is completely blocked by the system configuration.

### 4. No Permanent Delete Rule
Permanent deletion is disabled (`ALLOW_PERMANENT_DELETE = false`). All files moved to the quarantine folder are preserved with their original filenames and metadata to allow direct rollback.

### 5. Checksum Validation
To verify file integrity before and after operations, the executor:
1. Calculates the MD5 checksum of the source file before it is moved.
2. Performs a safe copy/move.
3. Calculates the MD5 checksum of the quarantined destination file.
4. Verifies that both checksums match perfectly.
5. Logs a checksum report for audit trails.

### 6. Restore Map Behavior
Every quarantine run produces a corresponding rollback restore script (`outputs/cleanup/restore_scripts/restore_quarantined_files_YYYY-MM-DD.sh`).
- This script is heavily commented and does not run automatically.
- Executing it will copy/move the files from the quarantine directory back to their original source directories.
- The script automatically recreates any parent directories if they have been deleted.

### 7. Future Deletion Boundary
A separate future deletion phase (e.g., Phase 12C) may handle permanent deletion of verified duplicates. That phase cannot be triggered until quarantined files have been reviewed and validated in quarantine for a predetermined monitoring period.

## 🛠️ Command Usage

Execute commands through the Safe Command Router:

```bash
# Get available commands
npm run command -- "quarantine-executor-help"

# Execute a dry-run to preview potential quarantine movements
npm run command -- "quarantine-executor dry-run"

# Execute the quarantine moves for staged duplicate briefs (requires --confirm)
npm run command -- "quarantine-executor execute-approved" --confirm

# Verify the integrity checksums of quarantined files
npm run command -- "quarantine-executor checksum"

# Generate/view the restore maps
npm run command -- "quarantine-executor restore-map"

# Check the status dashboard
npm run command -- "quarantine-executor status"
```
