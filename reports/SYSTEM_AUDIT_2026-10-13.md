# System Audit: duplicates, stale files, unused tools, projects and workflows

**Date:** 2026-10-13
**Scope:** `brilliantaire-os` (main at `c3b2054`), the `sentinel-os` checkout and remote, GitHub (branches, pull requests, Actions) and the account's cloud Routines.
**Method:** read-only. Content hashes over every tracked file, cross-references between `package.json`, `Taskfile.yml`, `config/commands.ts`, `scripts/`, `tools/`, `config/` and the root docs, the repo's own checks (`npm run audit`, `doc-drift`, `bridge-health`, `system-diagnostics`, `next`), a run of all 140 registered `-help` commands, and the GitHub and Routines APIs. Nothing was changed.
**Previous audit:** `reports/ROOT_AUDIT_2026-10-05.md`. Its findings F1 (phantom commands), F2 (Taskfile duplicates), F4 (registry guard) and F7 (counts) are fixed. This audit does not repeat them.

## Verdict

The code that runs is healthy. CI is green on main, the suite passes (699 tests), both typechecks are clean, every built-in audit passes, and all 140 help commands start. The weight is elsewhere:

| Area | Finding |
|---|---|
| Duplicates | 202 byte-identical copies under `outputs/` (115 groups), plus fixture and config duplicates |
| Stale | 913 tracked files under `outputs/`; 33 of its 53 folders have nothing newer than 4 June. 82 of 102 root docs untouched since 3 July. Scheduler status files from 31 May in both repos |
| Unused | 52 scripts nothing references; 34 npm scripts outside the Safe Command Router; 9 of 13 registry skills never used; 11 orphan test configs |

## 6. Recommended actions, in order

Each is reversible and small enough for one PR.

1. **Fix the three crashing commands** (§3.2) and add a CI step that imports every registered script, so a command that cannot start fails the build the way a type error does.
2. **Reconcile the three command lists** (§1.3): delete or implement the 5 `sentinel:*` tasks, give the 14 registry-only commands Taskfile tasks or drop the Taskfile mirror, and decide which of the 34 unrouted npm scripts belong in the router.
3. **Decide the 52 orphan scripts** (§3.1): register the ones that are real, move the rest to an `attic/` folder with a one-line note each, so the next recovery does not re-import them.
4. **Stop committing re-run copies** (§1.1): make the writers overwrite the dated file instead of adding a timestamped twin, delete the 202 identical copies, and consider ignoring `outputs/**/reports/` except a `latest` file, as `latest.json` already is.
5. **Refresh the four documents that describe the system**: `CLAUDE.md` (the sentinel-os line, the pjk commands' directory), `PROJECTS.md` (drop the 20 clones, move the Notes cell to a changelog, fix the PJK path, mark Dormant where §4.1 says so), `SYSTEM_STATUS.md` (current phase), `SENTINEL_SAFETY_GATE.md` (commands that exist).
6. **Branches**: delete the 6 merged-elsewhere and 4 superseded branches here, and the superseded ones in sentinel-os; close one of #202/#203 after applying §5.4; merge or close #81.
7. **Routines and schedulers**: check why today's Morning brief is stuck; align the local scheduler's approved list with its registered list in both repos; replace the copied `SCHEDULER_STATUS.md` with one each repo generates.
8. **Skills**: retire the 9 never-used `skills/registry.json` entries or wire them to something; say in `SYSTEM_STATUS.md` what `.agents/skills/` is for.
